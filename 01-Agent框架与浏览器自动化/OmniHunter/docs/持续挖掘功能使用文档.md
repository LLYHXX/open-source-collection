## 1. 功能概述

**持续挖掘**是本工具实现"挖一个漏洞 → 顺藤摸瓜挖出一片漏洞"的核心能力。它由三条相互配合的链路组成：

| 链路 | 触发方式 | 核心逻辑 | 入口 |
|---|---|---|---|
| ① 信息泄露自动深挖 | **全自动**（引擎扫描确认 info_leak 漏洞后） | 从泄露响应中提取子目标 URL / 凭据 / 内网 IP，递归进入下一轮扫描 | 无需操作，事件流自动展示 |
| ② POC 扩展分析 | **手动**（持续挖掘页提交已知 POC） | 自动生成关联变体并逐个复验，命中产出确认漏洞 | 侧边栏「持续挖掘」 |
| ③ 外接工具产物集成 | **手动**（上传专业工具文件） | 解析 PowerDesigner / PowerBuilder 等产物为结构化情报，供引擎复用 | 侧边栏「情报库」 |

### 1.1 工作原理图

```
┌─────────────── 链路①：自动深挖（引擎侧） ───────────────┐
│                                                          │
│  引擎扫描 → 确认 info_leak 漏洞（如目录列表、.env 泄露） │
│      ↓                                                   │
│  解析泄露内容：                                          │
│    · 目录列表/HTML 链接 → 同域子目标 URL                 │
│    · 备份后缀衍生（.bak/.sql/.zip…）→ 衍生探测 URL      │
│    · password=xxx / token=xxx → 凭据（脱敏）             │
│    · 10.x / 192.168.x / 172.16-31.x → 内网 IP           │
│      ↓                                                   │
│  子目标 URL → 递归引擎扫描（深度受限）                   │
│  凭据 / 内网 IP → 情报库（Intel）沉淀                    │
└──────────────────────────────────────────────────────────┘

┌─────────────── 链路②：POC 扩展（手动） ─────────────────┐
│                                                          │
│  粘贴已知 POC（URL 或 curl 命令）+ 命中正则             │
│      ↓                                                   │
│  生成 6 类确定性变体（后缀/前缀/大小写/参数值/编码/扩散）│
│      ↓                                                   │
│  逐个 HTTP 复验（永不抛异常，失败自动跳过）              │
│      ↓                                                   │
│  命中正则的变体 → 确认漏洞入库（可选关联任务）           │
│  命中响应 → 再走链路①的提取逻辑（持续挖掘闭环）          │
└──────────────────────────────────────────────────────────┘

┌─────────────── 链路③：外接工具（手动） ─────────────────┐
│                                                          │
│  上传 .pdm / .sr* / .sql / .env / .pem 等文件           │
│      ↓                                                   │
│  确定性解析 → 数据库表结构 / SQL 注入点 / 凭据          │
│      ↓                                                   │
│  入情报库（按 host 关联）→ 引擎检测时自动消费           │
└──────────────────────────────────────────────────────────┘
```

### 1.2 防失控设计

持续挖掘本质是"自动化递归"，本功能内置四重保险，确保不会失控扫描：

1. **深度限制**（`engine_max_depth`，默认 2 层）：子目标的子目标之后不再继续；
2. **总量限制**（`followup_max_urls`，默认 50 个）：单个任务自动深挖的 URL 总量封顶；
3. **同域过滤**：只跟进与目标同 host 的链接，外链记录在日志中交给人工判断；
4. **目标 SSRF 校验**：所有目标 URL 统一校验，内网/保留地址直接拒绝（防止把工具变成内网探测跳板）。

## 2. 适用场景

### 2.1 信息泄露后的顺藤摸瓜（链路①，自动）

| 场景 | 自动深挖动作 |
|---|---|
| 发现目录列表（Directory Listing） | 提取列表中同域文件/目录链接，逐个进入下一轮扫描 |
| 发现 `.env` / 配置文件泄露 | 提取 `password=`、`token=`、`api_key=` 等凭据（脱敏入情报库），并生成 `/backup.zip`、`/db.sql` 等衍生探测点 |
| 发现备份文件（如 `index.php.bak`） | 自动衍生同目录 `.old`、`.zip`、`.sql`、`.swp`、`.git` 等 15 类高价值后缀探测 |
| 泄露内容含内网地址 | 记录内网 IP 清单到情报库，作为 SSRF / 横向移动线索（不会自动探测内网） |

### 2.2 已知 POC 的关联漏洞扩展（链路②，手动）

| 场景 | 扩展分析动作 |
|---|---|
| 已知某文件存在未授权访问（如 `/backdoor.php`） | 自动尝试 `.bak` / `.old` / `.txt` / `~` 等后缀残留、`.backdoor.php` 编辑器前缀 |
| Windows / IIS 站点路径大小写不敏感 | 自动生成每段大小写互换变体 |
| 已知某参数存在注入（如 `?id=1`） | 自动替换参数值为 `'`（SQLi）、`../../etc/passwd`（穿越）、`{{7*7}}`（SSTI）、`<script>alert(1)</script>`（XSS）探针 |
| 疑似 WAF 绕过场景 | 自动生成单次 / 双重 URL 编码变体 |
| 同目录管理后台探测 | 自动尝试同目录 `admin.php`、`console.php`、`debug.php`、`phpinfo.php` 等 8 类常见文件 |

### 2.3 专业工具产物联动（链路③，手动）

| 场景 | 集成动作 |
|---|---|
| 掌握目标 PowerDesigner（.pdm）数据模型 | 解析出库表、字段、敏感列（如 password/id_card），供 SQL 注入利用时精准构造 |
| 掌握目标 PowerBuilder（.srw/.srd/.srf 等）源码 | 审计出拼接 SQL / 动态 SQL 注入 sink，标记为高危注入点 |
| 掌握建表脚本（.sql） | 提取表结构与字段，同上入库 |
| 拿到密钥 / 配置文件（.pem/.key/.env/.ini/.conf） | 识别敏感凭据并入情报库 |

## 3. 操作步骤

### 3.1 链路①：信息泄露自动深挖（零操作，全自动）

1. **创建任务**：进入「任务」页，创建任务并将模式选为**自研引擎**，目标填写授权站点 URL；
2. **启动任务**：引擎自动完成指纹前置 → 漏洞检测 → 复现验证；
3. **自动深挖触发**：当引擎确认**信息泄露（info_leak）**类漏洞后，自动提取子目标并递归扫描，无需任何人工操作；
4. **观察进度**：在任务详情的事件流中可看到 `[持续挖掘]` 前缀的日志，例如：
   ```
   [持续挖掘] http://target.com/uploads/: 发现内网地址 3 个: 10.0.1.5, 10.0.1.6, 192.168.2.10
   [持续挖掘] http://target.com/uploads/: 提取疑似凭据 2 条（已脱敏入情报库）
   [持续挖掘] 从泄露中提取 17 个子目标，递归扫描（深度 2/2）
   ```
5. **查看成果**：
   - 新发现的漏洞 → 「漏洞」页（带 CVSS 定级）；
   - 凭据 / 内网 IP / 子目标 → 「情报库」页（kind 为 `credential` / `leak`）。

> 提示：若想关闭自动深挖或调整深度/总量，见 [4.3 配置参数](#43-配置参数持续挖掘引擎侧)。

### 3.2 链路②：POC 扩展分析（手动，持续挖掘页）

1. **进入页面**：点击侧边栏「**持续挖掘**」；
2. **填写目标 URL**：目标站点根地址（如 `http://target.com`），用于 SSRF 校验与子目标同域过滤；
3. **（可选）关联任务**：从下拉框选择已有任务，**命中漏洞将自动入库到该任务**，便于统一管理与出报告；
4. **粘贴 POC 描述**：支持两种格式（任选其一）：
   - curl 命令：`curl 'http://target.com/config.php.bak'`
   - 纯 URL：直接粘贴含 `http(s)://` 的 URL，文本中出现 POST/PUT 字样会自动识别请求方法；
5. **填写命中正则**（强烈建议）：响应内容命中该正则才算"确认命中"，例如 `root:`（密码文件特征）、`DB_PASSWORD`（配置文件特征）。**留空时只报告变体可达性，不产出确认漏洞**；
6. **点击「开始扩展分析」**：系统生成最多 40 个变体并逐个复验（每个变体最长 10 秒，全程可能需要几分钟，请耐心等待按钮 loading 结束）；
7. **查看结果**：
   - **原始 POC 复验**卡片：原始请求的状态码、耗时、响应片段；
   - **变体复验结果**表格：每个变体的命中标记、HTTP 状态、方法、URL、变体说明、响应片段；
   - **持续挖掘产出**卡片：从命中响应中提取的子目标 URL、脱敏凭据、内网 IP（均已自动回灌情报库）。

### 3.3 链路③：外接工具产物上传（手动，情报库页）

1. **进入页面**：点击侧边栏「**情报库**」；
2. **填写关联 host**（建议）：如 `target.com`。情报按 host 检索，引擎在 SQL 注入利用 / IDOR 定位时按 host 自动关联消费；留空则以文件名作为键；
3. **选择文件并解析**：点击「选择文件并解析」，支持多类型文件（见 4.4 支持类型表），单文件 ≤ 10MB；
4. **查看解析结果**：页面顶部显示解析摘要（如"PDM: 28 张表 / 196 字段 / 5 个敏感列"），明细已入库；
5. **验证入库**：用类型筛选（数据库模型 `db_schema` / PB审计 `pb_audit`）刷新列表查看。

## 4. 参数说明

### 4.1 POC 扩展分析页参数

| 参数 | 必填 | 说明 |
|---|---|---|
| 目标 URL | ✅ | 目标站点地址，必须 `http(s)://` 开头；系统会校验并**拒绝内网/保留/链路本地地址**（防 SSRF） |
| 关联任务 | ❌ | 选择后，确认命中的漏洞自动以 `poc_expanded` 类型、`high` 级别、`pending` 状态入库到该任务 |
| POC 描述 | ✅ | 需包含 `http(s)://` URL 或 curl 命令；curl 的 `-X` 方法与 `-d/--data/--data-raw` 请求体会被解析（有请求体时方法自动升级为 POST） |
| 命中正则 | ❌（强烈建议） | 对变体响应正文做不区分大小写的正则匹配；只有命中才标记"确认"并入库；非法正则会被安全忽略（视为未命中） |

### 4.2 变体生成规则（自动，无需配置）

| 变体类型 | 示例（原始 `/backdoor.php?id=1`） | 说明 |
|---|---|---|
| 后缀变体 | `/backdoor.php.bak` `.old` `.txt` `.save` `.swp` `.orig` `.copy` `~` `.1` | 编辑器/备份工具残留，共 9 类 |
| 前缀点变体 | `/.backdoor.php` | vim/emacs 崩溃恢复文件习惯 |
| 大小写变体 | `/Backdoor.php`、`/backdoor.PHP` 等 | 逐段翻转，Windows/IIS 大小写不敏感场景 |
| 参数值变体 | `?id=1'`、`?id=../../etc/passwd`、`?id={{7*7}}`、`?id=${7*7}`、`?id=<script>...` | 前 3 个参数各替换 5 种高危探针 |
| 编码变体 | `%62ackdoor.php`、`%2562ackdoor.php` | 单次/双重 URL 编码 |
| 同目录扩散 | `/admin.php` `manager.php` `console.php` `debug.php` `install.php` `phpinfo.php` `test.php` `info.php` | 管理后台常见文件名 |

- 单次分析变体上限 **40 个**（超出的按生成顺序截断），自动去重；
- 所有变体继承原始 POC 的方法与请求体。

### 4.3 配置参数（持续挖掘引擎侧）

以下配置控制链路①的自动深挖行为（见「设置」页或后端 `config.py`）：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `engine_followup_enabled` | `True` | 总开关：确认信息泄露后是否自动提取子目标递归扫描。设为 `False` 完全关闭链路①（链路②不受影响） |
| `engine_max_depth` | `2` | 最大递归深度。`1` = 只挖一层（泄露点→子目标扫描，子目标发现的泄露不再跟进）；`2` = 两层 |
| `followup_max_urls` | `50` | 单个任务自动深挖的 URL 总量上限，达到后停止提取新子目标（防失控核心保险） |

### 4.4 外接工具支持类型

| 扩展名 | 工具/来源 | 解析产物（情报类型） |
|---|---|---|
| `.pdm` | PowerDesigner 数据模型 | 库表、字段、敏感列（`db_schema`） |
| `.srd` `.srw` `.srf` `.srs` `.sra` `.srp` `.sru` `.srj` | PowerBuilder 源码 | 拼接 SQL / 动态 SQL 注入点审计（`pb_audit`） |
| `.sql` | 建表脚本 | 表结构（`db_schema`） |
| `.env` `.ini` `.conf` `.config` | 配置文件 | 敏感凭据 / 配置项（`credential`） |
| `.pem` `.key` | 密钥文件 | 密钥情报（`credential`） |

单文件大小限制 **10MB**。

## 5. 使用示例

### 示例 1：备份文件挖掘（最典型）

**背景**：手工测试怀疑目标存在编辑器备份文件，已知 `/config.php` 存在。

```
目标 URL：http://target.com
关联任务：选择"某电商站点渗透测试"
POC 描述：curl 'http://target.com/config.php.bak'
命中正则：DB_PASSWORD|password\s*=
```

**点击「开始扩展分析」后系统会**：

1. 复验原始 POC（`/config.php.bak` 是否可达）；
2. 生成约 25 个变体：`config.php.old`、`config.php.txt`、`.config.php`、`%63onfig.php` 等；
3. 逐个请求并匹配正则；
4. 若 `config.php.save` 响应 200 且正文含 `DB_PASSWORD=` → 确认命中，漏洞自动入库到关联任务；
5. 从命中响应中提取到 `http://target.com/phpinfo.php` → 自动入情报库（kind=leak），凭据脱敏入库（kind=credential）。

### 示例 2：参数注入点扩散

**背景**：已知 `http://target.com/item.php?id=1` 是个注入点候选，想快速测试同页面其他探针。

```
目标 URL：http://target.com
POC 描述：http://target.com/item.php?id=1
命中正则：SQL syntax|MySQL|ODBC
```

系统会生成 `?id=1'`（报错注入探针）、`?id={{7*7}}`（SSTI 探针）、大小写变体等并逐一匹配数据库报错特征。

### 示例 3：PowerDesigner 模型联动（链路③+①②组合拳）

1. 从乙方交接 / 代码仓库拿到目标 `shop.pdm` 数据模型 → 情报库页上传，关联 host 填 `target.com`；
2. 解析得到 28 张表、5 个敏感列（`user.password`、`orders.amount` 等）入情报库；
3. 对 `?id=1` 跑 POC 扩展（示例 2），报错注入命中；
4. 引擎在 SQL 注入利用 / IDOR 定位时按 host 自动关联这些表结构，构造更精准的 payload（如按真实列名做 UNION 注入）。

### 示例 4：全自动深挖（链路①，无需填写任何表单）

创建引擎模式任务并启动后，引擎发现 `http://target.com/uploads/` 存在目录列表 → 自动提取列表内 17 个同域文件链接 → 逐个进入下一轮扫描 → 又在其中一个目录发现 `.env` → 提取 2 条凭据脱敏入库 + 衍生 `/backup.zip` 探测 → 深度耗尽（2 层）后自动停止。全程在任务事件流中以 `[持续挖掘]` 日志可见。

## 6. 注意事项

### 6.1 法律与授权（最重要）

- **仅对已获得书面授权的目标使用**。持续挖掘会显著增加请求量（最多 40 个变体 × 每个一次请求 + 递归子目标扫描），未授权使用涉嫌违法；
- 变体中的参数探针（`'`、`../../etc/passwd`、`<script>` 等）是**真实攻击 payload**，可能触发目标 WAF 告警或影响业务，请评估后再执行。

### 6.2 行为边界

- **内网目标不可扫**：所有入口（任务创建、POC 扩展）统一做 SSRF 校验，内网/保留地址直接拒绝。这是安全设计而非缺陷；
- **外链不自动跟进**：泄露响应中的其他域名链接只记录在 `notes` 中，需人工判断后再处理；
- **内网 IP 只记录不探测**：提取到的内网地址作为横向移动线索入情报库，工具不会主动向内网发起请求；
- **凭据脱敏存储**：情报库中的凭据只存脱敏值（如 `admi***ss`），原文需回到泄露响应原文中查看，避免敏感信息二次扩散。

### 6.3 技术边界

- **命中正则是判定核心**：留空时"命中"恒为否（只报可达性），且**不会产出确认漏洞、不会入库**；
- **soft-404 陷阱**：很多站点对不存在的路径返回 200 + 自定义错误页，导致"可达"≠"存在"。务必配合命中正则区分真实内容与错误页；
- **耗时预期**：40 个变体逐个复验，每个最长 10 秒，最坏情况约 7 分钟；前端已将接口超时放宽至 10 分钟，期间请勿关闭页面；
- **POST 变体局限**：变体只改 URL，POST 请求体原样继承，不生成请求体变体。

## 7. 常见问题解答

**Q1：为什么所有变体都显示"可达未命中"？**
A：三种可能：① 未填命中正则（此时 `hit` 恒为否，请补填后重跑）；② 变体返回的是自定义 404/错误页（soft-404），需换更精确的正则（如真实内容独有的字段名）；③ 正则写错——正则非法时系统安全地按"未命中"处理，可先用简单关键字（如 `root:`）验证。

**Q2：自动深挖没有触发，怎么排查？**
A：按顺序检查：① 漏洞列表中该漏洞的**类型是否为信息泄露（info_leak）**——只有这一类触发深挖；② 配置项 `engine_followup_enabled` 是否为 `True`；③ 任务事件流中是否有 `[持续挖掘] 子目标失败` 日志（单个子目标失败不中断整体）；④ `followup_max_urls`（50）总量是否已被更早的泄露点消耗完。

**Q3：POC 提交后提示"未能从 POC 描述中解析出 URL"？**
A：POC 文本必须包含 `http(s)://` 开头的 URL 或 `curl` 命令。从报告中复制时注意别把 URL 换行截断，也不要用 `<目标URL>` 这类占位符。

**Q4：确认命中了，但漏洞列表里没有？**
A：漏洞入库需要**关联任务**。未选任务时命中结果只在页面上展示，不入库。请重新执行并选择关联任务。

**Q5：变体数量为什么不足 40 个？**
A：变体生成有前提：后缀变体要求 URL 文件名含 `.`；参数值变体要求 URL 带 query；其余类型固定生成。生成后自动去重，URL 完全相同的变体只保留一个。

**Q6：情报库里凭据是 `***` 脱敏的，怎么用？**
A：情报库只保存凭据"存在性"与键名，供后续检测（弱口令、认证绕过）关联。完整值请回到对应漏洞的响应片段（evidence/snippet）中查看。

**Q7：上传 PDM 文件解析失败？**
A：确认文件是 PowerDesigner 导出的标准 XML 格式且声明了必要命名空间（`xmlns:a` / `xmlns:c`）；部分旧版本或手工编辑的 PDM 可能缺失命名空间，可用 PowerDesigner 另存一次再上传。

**Q8：能否对内网资产（如授权的内网靶标）使用？**
A：公网入口统一拒绝内网目标（防 SSRF）。内网授权测试请使用本工具部署在可达内网的机器上执行，或结合「移动靶场」做 APP/小程序流量回灌分析。

**Q9：深度 2 层会不会太少 / 太多？**
A：默认 2 层在"发现目录列表 → 扫描子文件 → 子文件再泄露 → 扫描再下一级"的典型链路上已经够用。结构极深的站点可观察到 `followup_max_urls` 先耗尽，此时深度不是瓶颈；若目标站点脆弱点集中，`1` 层即可控制噪声。

## 8. 最佳实践建议

1. **先确认原始 POC，再谈扩展**：执行扩展分析前，先用浏览器或 curl 确认原始 POC 真实可达。原始 POC 都不可达，变体大概率同样无效，白耗请求配额。

2. **命中正则宁精勿宽**：
   - ✅ 推荐：`root:`（passwd 文件）、`DB_PASSWORD`（配置文件）、`SQL syntax.*MySQL`（报错注入）、`<?php`（源码泄露）；
   - ❌ 避免：`error`、`test`、单个字母——过宽的正则会把错误页也判定为命中，产生误报入库。

3. **务必关联任务**：命中漏洞入库后才能进入统一的漏洞管理流（人工复审 → 报告输出），否则结果只存在于单次页面展示中。

4. **外接工具产物按 host 精确关联**：上传 `.pdm`/`.srw` 时 host 填写与扫描目标完全一致的域名（如 `www.target.com`），引擎按 host 匹配消费，写错则情报"沉睡"无法被利用。

5. **组合拳打法**（推荐工作流）：
   ```
   外接工具入库（PDM/PB 情报）
        ↓
   引擎全量扫描（自动深挖链路①跑完）
        ↓
   对高价值注入点/泄露点逐个跑 POC 扩展（链路②精修）
        ↓
   情报库复核（新凭据/子目标）→ 漏洞页人工复审 → 报告输出
   ```

6. **控制噪声**：对生产环境目标，建议将 `engine_max_depth` 调为 `1`、`followup_max_urls` 调小（如 20），先小范围验证再逐步放开。

7. **定期复盘情报库**：`leak`（子目标/内网地址）与 `credential`（脱敏凭据）是多次扫描的沉淀产物，下轮测试前先过一遍情报库，往往能直接命中历史遗留的敏感点。

8. **误报闭环**：若某类变体在某站点总是 soft-404 误报，记住该站点的错误页特征（如标题"404 not found"），下次把命中正则写成"真实内容特征 + 排除错误页特征"，持续提升检出精度。
